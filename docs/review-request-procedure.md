# GPT-5.5 レビュー依頼手順

この文書は、GPT-5.4 mini が変更を実装・調査するときに、GPT-5.5 へレビューを委譲する手順を定める。
会話の前提を知らなくても、この文書だけで依頼から修正後の再レビューまで実行できることを目的とする。
この手順は GPT-5.4 mini が GPT-5.5 を呼ぶためのものであり、GPT-5.5 自身が読む場合は再委譲せず自分で一次評価する。

## 必須ルール

- GPT-5.4 mini は、自分の確認を GPT-5.5 のレビューの代わりにしてはいけない。
- 実装や追加調査を始める前に、簡潔な作業プランを GPT-5.5 にレビューさせる。
- 実装後は、変更差分を GPT-5.5 にレビューさせる。
- レビューは必ず GPT-5.5 で行う。GPT-5.4 mini やこの会話の主エージェント自身の目視確認はレビューの代わりにしない。
- GPT-5.5 のレビュー本文を受領するまで、「レビュー完了」「問題なし」「Go」と判断しない。
- コマンドを起動しただけ、セッション ID が返っただけ、途中出力を得ただけではレビュー未完了とする。
- findings がある場合は修正し、同じ条件で再レビューする。
- findings がなくなるまで、修正と再レビューを繰り返す。
- GPT-5.5 を呼び出せない場合、GPT-5.4 mini が自分で代替レビューして先へ進んではいけない。

## 実行順序

1. 現状、目的、再現手順、変更予定を整理する。
2. 作業プランを GPT-5.5 にレビューさせる。
3. 指摘があればプランを直し、再度 GPT-5.5 にレビューさせる。
4. プランに Go が出てから実装・調査を行う。
5. 構文確認、関連テスト、`TUI` 以外の自動確認を行い、対象 diff hash と完了時刻を記録する。
6. `TUI` の実機確認に入る前に、現時点の差分を GPT-5.5 にレビューさせ、レビュー完了時刻と判定を記録する。
7. GPT-5.5 から `Go` が出たら、そのあとで `TUI` の実機確認を行う。ここでの `Go` は実機確認の開始許可に限る。`TUI` 開始時刻も記録する。
8. 実機確認の結果を差分に反映し、再度 GPT-5.5 にレビューさせる。
9. 指摘を修正して再検証する。
10. GPT-5.5 から findings なし、または明示的な Go を得るまで 8 と 9 を繰り返す。

## GPT-5.5 の呼び出し方

### 方法 A: サブエージェント

サブエージェント機能が利用できる場合は、次の条件で起動する。

- `model`: `gpt-5.5`
- `fork_context`: `false`
- 役割: コードレビューワー
- 対象: 作業プラン、または現在の未コミット差分
- 呼び出し側: GPT-5.4 mini

`fork_context: true` と `model: gpt-5.5` は併用しない。履歴を fork したサブエージェントは親のモデル設定を継承するため、モデル上書きと衝突する。
履歴を渡さないため、依頼文にはリポジトリの絶対パス、対象、目的、再現手順、検証済み事項、未検証事項を明記する。
依頼文には、GPT-5.5 が別のレビューワーを起動せず、自身で一次評価を完了することも明記する。
依頼文には、追加の `codex review`、追加のサブエージェント起動、自己再委譲を禁止する旨も含める。
レビュー結果を受領したら、不要になったサブエージェントを閉じる。

起動条件の例:

```text
agent_type: default
model: gpt-5.5
fork_context: false
message: <下記の依頼文を、必要な文脈を埋めて渡す>
```

### 方法 B: Bash フォールバック

サブエージェントを起動できない場合だけ、対象リポジトリのルートで `codex exec` を使う。
`codex review` と `codex exec review` は `reviewer` スキルを再読して同じレビュー経路に入ることがあるため、Bash フォールバックとして使わない。

```sh
codex exec -m gpt-5.5 -s read-only -C /path/to/repo \
  --ephemeral --ignore-user-config '
あなたは GPT-5.5 のコードレビューワーです。
現在の未コミット差分をレビューしてください。
別のサブエージェント、reviewer スキル、codex review を呼び出さず、
自身で差分を読み、一次評価を完了してください。

変更目的:
- <変更目的>

再現手順:
- <変更前の失敗手順とエラー>

実施した検証:
- <コマンドと結果>

未検証:
- <実機や対話操作など、未確認の経路>

重点確認:
- バグ、回帰、セキュリティ、破壊的変更
- 新規インストールと既存キャッシュの両方
- TUI の起動直後と入力後の両方
- print 分岐と TUI 分岐の差
- 非同期処理の継続中に finally や cleanup が走らないか
- helper や shim が全 VM context に届くか
- ソース、生成 tarball、インストール済みファイルが同一か
- audited JSON、manifest、README、実 tarball の整合
- 実機未確認の状態を termux_verified にしていないか
- 失敗を直接検出する回帰テストがあるか

出力条件:
- findings を重大度順に記載する
- 各 finding に file/line、根拠、発生条件、影響、最小修正案を付ける
- 問題がなければ「Go」と残余リスク、未検証経路を明記する
- 実装やファイル編集は行わず、レビュー結果だけを返す
'
```

この経路で `reviewer` スキルの再読、`SpawnAgent`、別の `codex` 起動が表示された場合は再帰と判定し、成功扱いにしない。
対象プロセスを中断し、不要なサブエージェントや残存セッションを閉じて一度だけ再試行する。それでも結果本文を得られなければ作業を停止する。

### 再帰・起動失敗の判定

次の状態はレビュー未完了とする。

- `Full-history forked agents inherit the parent agent type...` が出た
  - 原因: `fork_context: true` と `model: gpt-5.5` の併用
  - 対処: `fork_context: false` にして、文脈を依頼文へ明記する
- GPT-5.5 がさらに `codex review` または `spawn_agent` を実行した
  - 原因: GPT-5.5 側で `reviewer` スキルを再帰実行している
  - 対処: 「別のレビューワーを呼ばず、自身で一次評価する」を依頼文へ明記する
- セッション ID だけが返り、最終本文が返らない
  - 対処: 完了扱いにせず、既存セッションを閉じて一度だけ再試行する
- 同時実行上限で起動できない
  - 対処: 完了済み・不要なサブエージェントを閉じてから再試行する

```text
あなたは GPT-5.5 のコードレビューワーです。
以下の作業プランを、実装前にレビューしてください。
別のサブエージェント、reviewer スキル、codex review を呼び出さず、
自身で一次評価を完了してください。

目的:
- <直す問題を1文で記載>

再現手順・観測事実:
- <実行コマンド>
- <実際のエラー>
- <事実と推測を分けて記載>

作業プラン:
1. <調査内容>
2. <変更予定>
3. <テスト予定>

確認事項:
- 原因の仮説が観測事実と整合するか
- 調査漏れ、破壊的変更、回帰、供給網リスクがないか
- テストが失敗経路を直接検証するか

- findings を重大度順に記載する

```

## レビュー結果の判定

次のいずれかを満たした場合だけ Go とする。

- GPT-5.5 が findings なしと明記し、Go を出した。
- `TUI` の実機確認の前に GPT-5.5 が `Go` を出した場合は、実機確認の開始許可としてのみ扱う。
- 指摘済み findings をすべて修正した後の再レビューで、GPT-5.5 が Go を出した。

次は Go ではない。

- GPT-5.4 mini 自身が「問題なさそう」と判断した。
- 構文チェックや `git diff --check` だけが成功した。
- GPT-5.5 のプロセスを起動できたが、結果本文を受領していない。
- レビューがタイムアウト、中断、`^C`、非ゼロ終了になった。
- GPT-5.4 mini やこの会話の主エージェントが自分で見て「問題なさそう」と判断しただけで、GPT-5.5 の本文を受け取っていない。
- 初期画面だけ表示でき、入力後の経路を確認していない。
- `TUI` の実機確認を GPT-5.5 の `Go` より先に始めた。
- 作業ツリーの tarball を更新したが、インストール済み package を確認していない。

## レビュー記録

レビュー結果は、`docs/review-logs/YYYY-MM-DD-HHMMSS-topic.md` に保存する。

必須項目:

- 対象 diff hash
- レビュー完了時刻
- レビューしたモデル名
- 判定 (`Go` / `findings`)
- `TUI` 開始時刻
- `TUI` 終了時刻
- tarball hash
- 作業ツリー hash
- GPT-5.5 への依頼文
- GPT-5.5 の応答全文
- 実行したコマンド
- 各コマンドの結果
- 未検証経路とその理由

## 重点確認ポイントへの赤入れ

重点確認ポイントは、単なるチェック項目ではなく、レビュー依頼時に証拠を添える必要がある。

- 「新規インストール時にだけ起きる失敗」
  - 修正: キャッシュを使った試験と、空のキャッシュでの試験を分けて結果を書く。
- 「既存キャッシュがある環境だと見逃す回帰」
  - 修正: workdir 内の生成済み JS が再利用・上書き・削除のどれになるか確認する。
- 「TUI の入力後に初めて通る経路」
  - 修正: 起動確認だけでは不足。少なくとも一度入力し、応答または次画面まで確認する。
- 「print 分岐と TUI 分岐の両方で必要な helper の欠落」
  - 修正: 同名 helper の存在確認だけでは不足。両分岐から実際に呼ばれることを確認する。
- 「監査 JSON の値が実 tarball を指しているか」
  - 修正: JSON、配布 tarball、tarball 内 metadata の hash、size、integrity を機械的に照合する。
- 「tarball と作業ツリーの runner が同じか」
  - 修正: `sha256sum` と `cmp` で機械的に照合し、差分を見た時刻を記録する。
- 「README / manifest / audited JSON の整合」
  - 修正: 生成スクリプトの成功だけでは不足。生成後の値を比較する。
- 「termux_verified に昇格してよいか」
  - 修正: 実機 TUI の入力後経路を未確認なら昇格させない。

## レビュー例

このメモを作成した時点で実際に確認した差分の例を示す。
GPT-5.4 mini が次回 GPT-5.5 に依頼するとき、再確認を求めるべき具体例として使う。

### High: print 分岐の待機が固定値になっている

- 対象: `packages/claude-code/lib/termux-run-claude-native.sh`
- 観測: print 分岐は `maybePromise` の完了後に `CLAUDE_TERMUX_PRINT_WAIT_MS` で指定した時間だけ待ってから `finally` に進む。待機は固定値ではなく設定可能に戻す必要がある。
- 既知事例: 以前はこの待機が 5 秒固定になっており、レビュー指摘の対象になった。
- 影響: 固定値のままだと、実行時間の予測不能化や、別の待機戦略へ移す際の障害になる。
- 最小修正案: 待機時間を環境変数で上書き可能にし、デフォルト値も明示する。
- 必須テスト: print 分岐が環境変数の値を使うこと、bootstrap 分岐にはこの待機が入らないことを確認する。

### High: 作業ツリーとインストール済み package が一致していない

- 観測: 作業ツリーと `/data/data/com.termux/files/usr/lib/node_modules/@bash0816/claude-code/lib/termux-run-claude-native.sh` の SHA-256 が異なる。
- 影響: tarball を再生成しただけでは、`claude` コマンドの実行結果に変更が反映されない。作業ツリーの検証と実機再現が別コードを対象にしてしまう。
- 最小修正案: 供給網確認後に、承認された方法でローカル package を導入し、実行中ファイルの hash を照合してから再現試験する。
- 必須テスト: `command -v claude`、実体パス、runner の hash、package version を記録する。

### Medium: バンドル文字列の完全一致置換が壊れやすい

- 対象: `rewriteNativeChunkSource`
- 観測: `Izq` 修正は minify 後の関数名、変数名、空白、文全体の完全一致に依存する。
- 影響: upstream の小変更や、置換順序の違いで修正が無言で適用されない。
- 最小修正案: 置換件数を検証して期待数と違えばエラーにする。可能なら関数全体ではなく、危険な条件式だけを狭く置換する。
- 必須テスト: 未修正 fixture、修正済み fixture、表記揺れ fixture に対する置換結果と冪等性を検証する。

## 完了報告

完了時は次を短く報告する。

- GPT-5.5 の最終判定
- 修正した findings
- 実行したテストと結果
- 未検証経路と残余リスク
- 変更したファイル
